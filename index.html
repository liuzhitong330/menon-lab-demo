Motivation State & performance Across tasks Relevance

The Menon Lab studies how changing brain-network states support cognition. Its 2024 multi-demand study links time spent in a shared state to performance across different tasks. A useful next question is: how much individual-level information does that association actually carry?

I built a small audit of the published paired data: compare the original association with a leave-one-out linear estimate, inspect influential observations, and test whether the result depends on the task or brain-region definition.

How it works

Each point is one exported brain–behavior pair from Cai, Taghia & Menon (2024). Occupancy is the fraction of time assigned to the shared brain state. For each held-out observation, a line is fitted to all remaining pairs and compared with their mean performance.

The authors already evaluated multivariate CCA with leave-one-out prediction. This complementary audit asks a narrower, single-feature question and adds a mean baseline and observation-level diagnostics. The original neural features remain fixed: this is not independent validation.

Method

Result

Positive = lower error than the training-only mean. Zero = no gain. Click a task to inspect its observations above.

What this lets the lab do: identify readouts whose apparent promise changes with the error criterion before choosing a validation endpoint. These small, post-publication differences are not a statistically established task ranking.

Where Cathy adds value: one consistent benchmark across seven published task/session datasets, with explicit baseline, units, coverage and sensitivity checks.

The four DMCC tasks reuse one cohort, and the two HCP sessions reuse another. They are not seven independent replications. No observations are pooled, and source-row numbers are never assumed to identify the same person across sheets.

Why this matters for the lab

A network state can explain differences across a cohort without being a precise personal predictor. This audit offers a practical way to decide what needs checking before carrying a shared-state readout into a new cognitive dataset. This is an inferred research opportunity, not a claim about an internal lab bottleneck.

A sensible next test would fix the task and outcome in advance, retain participant/run IDs and motion covariates, and learn both the state model and readout on training data only. An untouched cohort could then test whether occupancy adds useful information beyond demographic, behavioral and motion baselines.

Methods note

Inputs: the paper’s CC BY 4.0 Source Data workbook, seven prespecified paired sheets and one stop-signal ROI sensitivity sheet. Values are preserved; occupancy is displayed as a percentage. Performance remains in source units because some published transformations cannot be reconstructed unambiguously. No missing values are imputed and no untested observations are manufactured.

Coverage, interpretation and reproducibility

Exported pairs / reported cohort size: AxCPT 50/50, CuedTS 49/50, Sternberg 50/50, Stroop 48/50, SST 44/45, relational session 1 90/90 and session 2 87/90. Supplementary Methods section H reports a ≥3-SD exclusion rule for univariate analyses. This audit retains every exported pair; it does not reconstruct the exact exclusion mask or apply more filtering. Stable participant IDs are not supplied in these sheets. The alternate SST sheet has 44 matching behavioral values in the same order; this numerical match is not an independently verified identity linkage.

OLS includes an intercept. Every held-out prediction and mean baseline use only the other rows. RMSE and MAE improvements are 100 × (1 − model error / baseline error). Leave-one-row-out correlation ranges measure influence, not confidence intervals. This is reuse of already fitted, filtered and selected published features, not raw-MRI reproduction, external validation, a clinical predictor or a causal test.

Code/data repository inspected and used: SCSNL release, pinned commit cfe1931. Source data: article supplement; archived repository data: Zenodo 10702914. See the reproducible analysis for the exact adapted upstream check and hashes; this does not reproduce the full BSDS/CCA workflow.
